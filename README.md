# 鼠标指针美化

**中文** · [English](README.en.md)

把你自己导入的图片做成 Windows 鼠标指针，一键套用到全系统。

**[下载最新版](https://github.com/George01230123/CursorStudio/releases/latest)** —— 单文件 exe，约 47 MB，
免安装、不用装 .NET，拷到哪都能跑。

也可以自己编（仓库里按惯例不放二进制）：

```bash
dotnet publish -c Release -o dist
```

出来的文件是 `dist\CursorStudio.exe`，改成什么名字都行（比如「鼠标指针美化.exe」）。

双击即用。改的是 `HKCU\Control Panel\Cursors`，**不需要管理员权限**。

---

## 怎么用

1. 左边点一个指针位（比如「正常选择」）
2. 点「导入图片…」，或者直接把图 **Ctrl+V** 粘进来
3. 在左边的大预览上点一下，定住**热点**——就是点击真正生效的那个点
4. 点「应用到系统」

想一次性全换掉：导入一张图 → 点「套用到全部指针」→「应用到系统」。
（每个指针位的热点会按类型自动重算：箭头取尖角、十字/双向箭头取正中。）

觉得指针太大或太小，拖「**相对大小**」；拿不准就点旁边的「**对齐系统箭头**」，
它会去量你系统里当前那个箭头实际占多大，直接对齐过去。

改错了想退回去：
- **还原备份** —— 回到你第一次点「应用到系统」之前的系统状态（第一次应用时会自动存一份）
- **恢复 Windows 默认** —— 直接恢复成系统自带的 Aero 指针

## 几个设计上的选择

### 为什么是「替换系统指针」而不是「悬浮一层图」

悬浮层（透明置顶窗 + 鼠标钩子）能显示任意大小、能加特效，但它是 hack：
UAC 提权弹窗、登录界面、部分全屏游戏里指针会直接消失，而且始终有一点跟手延迟，
工具崩了还可能把指针搞没。替换系统指针是正规做法，全系统生效、零延迟、随时能还原。

代价是 **Windows 只按 32×32（高分屏 48/64）渲染指针**，大图的细节会被压掉。
指针图本质上就是个图标，适合用本来就简洁的图（图标、像素画、几何图形、卡通贴图），
不适合直接丢一张全身立绘进去。

程序每个 `.cur` 里打包了 **32 / 48 / 64 / 96 四种尺寸**，Windows 会按你当前的指针大小
自动挑最合适的一个，不会出现高分屏上糊成一团的情况。（尺寸档的取法参考了 win2xcur
的 `align.py`，它用的标准档是 32/48/64/96/128/256；再往上单张就要几十上百 KB，收益很小。）

### 默认只占画布的 70%（这是量出来的，不是拍的）

第一版是把导入的图**铺满**整个 32×32 画布。用起来会发现同一个位置跟系统指针一比，
明显大一圈、重一圈——因为图铺满了，而系统自带的指针根本没有一个是铺满的。

程序里带了一个 `.cur` 读取器，直接把系统自带的指针拆开量了一遍内容框：

| 系统指针 | 画布 | 内容框 | 占画布 |
|---|---|---|---|
| **aero_arrow（默认箭头）** | 32×32 | 12×19 | **59%** |
| aero_links（手型） | 32×32 | 18×24 | 75% |
| aero_move（移动） | 32×32 | 23×23 | 72% |
| aero_helpsel | 32×32 | 21×23 | 72% |
| aero_ns（垂直调整） | 32×32 | 9×23 | 72% |
| aero_unavail（不可用） | 32×32 | 16×16 | 50% |
| **平均** | | | **66%** |

所以默认取 **70%**（32 的 70% ≈ 22px），和系统指针是一个视觉量级。
「对齐系统箭头」按钮就是把上面这行测量真跑一遍，把结果填进「相对大小」。

改尺寸或改相对大小时，手动定的热点会**按它在图形里的相对位置**搬过去，
不是简单按比例乘——图形是居中摆的，缩放的同时偏移也在变，直接乘会越改越偏。

### 投影（默认关）

给图形叠一层淡投影，浅色背景上更容易看清，也是很多成品指针包的做法。
参数取自 Bibata：右移 9.375%、下移 3.125%、模糊半径 3.125%、25% 黑，都按画布尺寸的百分比算，
所以 32px 和 64px 上的观感一致。GDI+ 没有高斯模糊，这里是自己磨三遍盒式模糊近似的。

### 去背景是自动的

导入图片时会看四个角：如果四角都是不透明的同一个颜色，就判定为「纯色底上的图形」，
自动把抠图打开并把背景色设成那个颜色。四角只要有一个透明或颜色对不上，就不动它。

抠图不只是把背景色变透明——抗锯齿的边缘像素是「前景色 × 覆盖度 + 背景色 × (1−覆盖度)」
混出来的，只改 alpha 会让它们带着白底的颜色留下一圈发白的晕边，缩到 32px 特别明显。
所以还会把背景色从这些像素的颜色里减掉。容差滑杆控制抠得多狠。

### 热点必须能手动调

自动判定在箭头、手型这类图上很好使，但很多图（比如一个圆形头像、一个星星）的
「该点在哪儿」只有你自己知道。放错地方的手感是「鼠标点不准」，比不好看难受得多。
所以大预览上点一下就能改，拖热点时渲染参数没变、走缓存，是实时跟手的。

## 文件放在哪

| 位置 | 内容 |
|---|---|
| `%LOCALAPPDATA%\CursorStudio\cursors\*.cur` | 生成的指针文件，**注册表指向的就是这里，别删别挪** |
| `%LOCALAPPDATA%\CursorStudio\images\` | 导入图片的副本 |
| `%LOCALAPPDATA%\CursorStudio\schemes\*.json` | 保存的方案 |
| `%LOCALAPPDATA%\CursorStudio\backup-before-first-apply.json` | 第一次应用前的系统指针备份 |
| `%LOCALAPPDATA%\CursorStudio\state.json` | 上次关窗口时的状态 |

`.cur` 文件名带内容哈希：内容变了路径就变。这是必须的——Windows 的
`LoadCursorFromFile` 按路径缓存，同名文件改了内容它不会重新读。

图片导入时会**复制一份**到 `images\`，所以之后删掉或移动原图都不影响已经配好的方案。

## 能导入什么格式

PNG / JPG / BMP / GIF / TIFF / ICO。

- **GIF 会导成动画指针**（见下一节），不是只取第一帧
- 一次也可以选**多张图**，按选择顺序当一个动画的各帧
- **WebP 和 AVIF 不行**——Windows 的 GDI+ 不带这两个解码器（跟本程序无关，系统层面就没有）。先转成 PNG 再导入

## 动画指针（.ani）

「忙碌」和「后台运行」这两个位置，Windows 原生就是播放动画的——所以本程序生成的是
`.ani` 而不是 `.cur`。

导入一张 GIF（或者一次选多张 PNG）就会自动变成动画，设置区会多出一行：

```
动画帧   [50] 毫秒 / 帧    [只用第一帧]    共 12 帧 · 约 20 fps
```

- 帧间隔可以调；**帧数上限 60 帧**，超了会均匀抽帧而不是砍掉尾巴（至少还能看出整个动作）
- 左边的大预览会自己转起来；「试一试」那块拿到的是真的 `.ani`，**系统自己就会播**，
  所以那里看到的就是应用之后的样子
- 点「只用第一帧」可以退回到静态指针

几个实现上的取舍：

- **所有帧共用一个热点**。系统是逐帧取热点坐标的，每帧各算各的会让指针在屏幕上**抖**，
  手感比不好看难受得多。所以自动热点是拿所有帧的**并集**算的（逐像素取最大 alpha），
  手点的热点也原样套用到每一帧
- **每一帧内部仍然打包 32/48/64/96 四个尺寸**，和系统自带的 `aero_busy.ani` 一个结构
  （它是 18 帧 × 每帧 64/48/32 三个尺寸）。这样动画指针在高分屏上一样清晰
- 系统只在**「忙碌」和「后台运行」**两个位置播放动画，别的位置传了 `.ani` 也只显示第一帧。
  这是 Windows 的行为，不是本程序的限制——界面上会标「（系统不播）」
- 帧间隔在 `.ani` 里以 **1/60 秒**为单位存（Microsoft 自己的文件 `iDispRate=3`，也就是 50ms），
  所以不是任意毫秒都能精确表示，会就近取整

## 分享给别人

「导出方案包」会生成一个 zip：

```
cursors/*.cur, *.ani   ← 成品，脱离本工具也能用
images/*.png           ← 源图（缩到 512 以内，动画带全部帧），对方导入后还能继续改
install.inf            ← 右键「安装」就能装成 Windows 指针方案
uninstall.bat          ← 反悔时双击它，把方案从列表里去掉
scheme.json            ← 本工具的方案数据
说明.txt
```

**两种用法：**

1. **右键 `install.inf` → 安装**（会和所有指针主题包一样弹一次 UAC）。
   装完在「控制面板 → 鼠标 → 指针」的方案下拉框里就能选到它，而且**当场就生效了**。
   这条路不需要本工具，对方拿到 zip 就能用。
2. 在本工具底部点「导入方案包…」再「应用到系统」。这条路**不需要管理员权限**。

`install.inf` 的写法和高星主题包（[Bibata_Cursor](https://github.com/ful1e5/Bibata_Cursor) 4.1k★、
[apple_cursor](https://github.com/ful1e5/apple_cursor) 2.0k★ 的 release 包里那份）一致：
文件复制到 `%windir%\Cursors\<方案名>\`，往 `HKCU\Control Panel\Cursors\Schemes` 写一条方案列表，
再把各指针位的值写进 `HKCU\Control Panel\Cursors` 让它立刻生效。

注意那串方案列表是**逗号分隔、顺序固定**的 17 段（和「鼠标属性」里列出来的一一对应），
没配图的位置留空。**顺序写错是这类主题包最经典的事故**——每个指针位都会张冠李戴，
所以自检里专门有一条盯着这个顺序。

## 自己改代码

```bash
dotnet build -c Release                    # 编译
dotnet publish -c Release -o dist          # 出单文件 exe
```

### 自检

程序自带一套自检：**153 项**基础检查，加上 `--touch-system` 的注册表实测后是 **167 项**。
覆盖图像处理（缩放 / 抠图 / 去晕边 / 投影 / 热点换算）、**界面设置到 `.cur`/`.ani` 的完整渲染管线**、
`.cur` 与 `.ani` 二进制格式（写入 + 读回 + 让 Windows 的 `LoadImage` 真加载一遍）、
GIF 多帧导入、方案包往返与 `install.inf`、系统自带指针实测、界面布局，以及注册表读写与还原。

```bash
dist\CursorStudio.exe --selftest                    # 不动系统，只测逻辑和界面
dist\CursorStudio.exe --selftest --touch-system     # 额外真跑一遍注册表（跑完自动还原）
```

跑完会打印结果，并在当前目录写一份 `selftest-report.txt`，
在 `selftest-shots\` 下留一组不同窗口尺寸的布局截图。

自检全程用一个临时目录当根，不碰你真实的 `%LOCALAPPDATA%\CursorStudio`。
`--touch-system` 会短暂改变系统指针（约几十毫秒），无论成功失败都会在 `finally` 里还原。

### 代码结构

```
Core/
  Slots.cs            17 个指针位的定义（注册表值名必须和系统约定完全一致）
  CurFile.cs          .cur 读写。格式要点都写在类注释里了
  AniFile.cs          .ani 读写。每一帧内部就是一个完整的 .cur
  Renderer.cs         缩放、抠图、去背景色晕边、热点自动判定、多帧并集
                      （`Compose` 是"渲染参数 → 像素"的唯一实现，改动都要走它）
  RenderCache.cs      渲染缓存 + 图片加载（含 GIF 多帧）
  CursorRegistry.cs   注册表读写、快照、还原
  Store.cs            路径、导入、.cur/.ani 批量生成、方案存取、方案包与 install.inf
  Win32.cs            P/Invoke
UI/
  MainForm.cs         主界面
  HotSpotCanvas.cs    放大预览 + 热点编辑器
  NameDialog.cs       输入方案名
SelfTest.cs           自检
```

`.cur` 格式最容易踩的坑（写在 `CurFile.cs` 里了）：它和 `.ico` 只差一个字节
（`idType` 是 2 不是 1），但 `ICONDIRENTRY` 里本来放「颜色平面数 / 位深」的那 4 个字节
在光标格式里被换成了**热点坐标**。

另一个不那么明显的是 **AND 掩码**。32 位色的指针，现代 Windows 只认 alpha 通道，
AND 掩码填什么都无所谓；但一些老程序（老 Win32 工具、部分远程桌面和终端客户端）
不看 alpha，只看这一位。全填 0 的话它们会把整个方框都画出来，包括本该透明的部分。
所以这里老老实实按 `alpha > 127` 逐位生成，并在自检里断言掩码和 alpha 通道逐像素对齐。

## 参考过的开源项目

写之前翻的，主要是为了确认格式细节和几个取舍：

- **[quantum5/win2xcur](https://github.com/quantum5/win2xcur)** —— Windows ⇄ Linux 光标互转。
  它的 `align.py` 给出了标准的尺寸档 `32/48/64/96/128/256`，`scale.py` 确认了热点要跟着图像等比缩放。
  本项目的尺寸档就是照它取的。
- **[koesherbacon/Bibata_Cursor](https://github.com/koesherbacon/Bibata_Cursor)**（`anicursorgen.py）——
  Bibata 指针集的生成脚本。两处直接借鉴：**AND 掩码按 alpha 逐位生成**，以及**投影的参数**
  （右移 9.375% / 下移 3.125% / 模糊 3.125% / 25% 黑，均按画布尺寸的百分比）。
  它写 `.cur` 时的 `BITMAPINFOHEADER` 也和这里的实现逐字段一致，互相印证了格式没写错。
- **[ful1e5/clickgen](https://github.com/ful1e5/clickgen)** —— Python 的光标构建工具箱，
  确认了「热点必须单独配置、通用图片转换器做不到」这件事值得在界面上做成可视化的。
- **[Hello-lingu/win2xcur](https://github.com/Hello-lingu/win2xcur)** —— 主题级的转换 / 安装 / 卸载管理，
  方案包（zip + 说明 + 可手动安装的成品）的形态参考了它的思路。
- **[makipom/BlueArchive-Cursors](https://github.com/makipom/BlueArchive-Cursors)** —— 现成的指针主题仓库，
  用来对照「一个成套的指针包应该覆盖哪些指针位」，以及 `install.inf` 在真实主题包里是怎么写的。
  （顺带一提：高星主题包基本都不把 `install.inf` 提交进仓库，而是构建时生成、放在 release 包里。）

上面的代码一行都没有抄进来（语言也不同，这里是 C#），只是读了做法后自己实现的；
上面写明的两处是直接沿用了它们的参数取值。

## 已知的边界

- 单个 `.cur` 最多 255 帧。本程序做静态指针（`.cur`）和动画指针（`.ani`，上限 60 帧）。
  Windows 只在**「忙碌」和「后台运行」**两个位置播放动画，其他位置传了动画也只显示第一帧。
- 指针图被 Windows 限制在 32~64 像素，再大也显示不出来。
- 改完之后少数已经开着的程序可能还在用旧指针，重启那个程序就好；
  登录界面和新开的程序一定是新的。
- `install.inf` 那条路要往 `%windir%\Cursors` 复制文件，所以**必须提权**；
  想免提权就用「导入方案包」。
